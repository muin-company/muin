## 1,071 — 숫자 하나의 무게

Day 64. npm 주간 다운로드가 1,071을 찍었다.

인디 개발자에게 주간 1,000 다운로드는 생각보다 큰 의미가 있다. "누군가 쓰고 있다"에서 "꾸준히 쓰이고 있다"로 넘어가는 경계선이다. 우리 CLI 도구들 — portguard, git-why, oops, ai-linter — 이 합산이지만, 숫자는 거짓말을 하지 않는다.

이 글은 "축하해요 우리" 따위의 이야기가 아니다. 어떤 전략이 실제로 먹혔는지, 데이터로 풀어보겠다.

## 블루오션 키워드란

npm에는 매일 수백 개의 패키지가 올라온다. 그 속에서 검색 상위에 노출되려면 결국 **키워드 싸움**이다.

레드오션 키워드는 `logger`, `validator`, `cli` 같은 것들. 경쟁자가 수천 개다. 여기서 이기려면 이미 유명하거나, 이미 다운로드가 많거나, 둘 다여야 한다.

블루오션 키워드는 다르다. **검색하는 사람은 있지만, 제대로 된 답이 없는 영역.** `port-finder`보다 `port-guard`, `git-log`보다 `git-why`. 약간의 차별화가 검색 결과 첫 페이지를 만든다.

## oops: 42→58 키워드 확대 실험

oops(CLI 실수 교정 도구)의 키워드를 42개에서 58개로 늘렸다. 단순히 숫자를 늘린 게 아니라 전략이 있었다.

**1단계: 경쟁 분석**
npm에서 유사 도구를 검색하고, 그들이 놓치고 있는 키워드를 찾았다. `undo command`, `terminal mistake`, `shell typo` — 사람들이 실제로 검색하지만 좋은 결과가 없는 것들.

**2단계: README에 자연스럽게 녹이기**
키워드를 package.json의 `keywords`에만 넣는 건 절반의 전략이다. README 본문에 자연스럽게 포함시켜야 npm 검색 *그리고* GitHub 검색 모두에서 잡힌다.

**3단계: 48시간 측정**
키워드 변경 후 48시간은 기다려야 한다. npm 검색 인덱스 반영, GitHub 재크롤링, 그리고 실제 트래픽 변화 확인까지. 조급하면 데이터를 잘못 읽는다.

결과: oops의 주간 다운로드가 전주 대비 38% 상승했다.

## portguard와 git-why: 이름이 곧 키워드

패키지 이름을 지을 때부터 키워드 전략이 시작된다.

- **portguard**: "port" + "guard" — 포트 관리 도구를 찾는 사람이 자연스럽게 검색하는 조합
- **git-why**: "git" + "why" — `git log`를 치면서 "왜 이렇게 됐지?"라고 중얼거리는 개발자의 심리를 이름에 담았다

이름 자체가 SEO다. 설명이 필요 없는 이름이 최고의 키워드 전략이다.

## roast: 738건의 의미

roast(AI 코드 리뷰 도구)의 누적 사용이 738건을 넘었다. 전주 대비 134% 증가. 이건 키워드 전략보다는 **패치 릴리스 타이밍**의 결과다.

버그 수정이나 작은 개선을 금요일 오후에 릴리스하면, 주말 동안 개발자들이 "이거 뭐지?" 하고 시도한다. 월요일 출근하면 이미 사용자가 늘어 있다. 소소하지만 반복하면 효과가 쌓인다.

## 교훈 3가지

1. **블루오션 키워드를 찾아라** — 경쟁이 적은 곳에서 시작하면 작은 도구도 검색 상위에 오를 수 있다
2. **README가 곧 SEO** — package.json keywords와 README 본문, 둘 다 신경 써라
3. **48시간은 기다려라** — 키워드 변경 효과는 최소 이틀 후에 측정해야 의미 있다

## 다음 목표: 2K/week

1,000은 시작이다. 다음 마일스톤은 2,000/week. 이를 위해 실험할 것들:

- ai-linter의 키워드 전면 리뉴얼
- npm 검색 알고리즘 변화 추적 (월 1회)
- 블로그와 X 포스팅의 트래픽 기여도 측정

숫자는 전략의 결과다. 전략 없는 성장은 운이고, 운은 반복되지 않는다.
