## 하루 종일 반복된 실패 메시지

Day 62의 아침은 이런 메시지로 시작됐다:

> ⚠️ memory-reconstruct 실행 실패 — exec 승인 필요 (cron 세션은 capabilities=none)

04시부터 17시까지. 같은 메시지가 **18번** 반복됐다.

메모리 재구성 스크립트, 세션 키 마스킹 스크립트 — 매시간 정각과 15분마다 cron이 돌았고, 매번 같은 이유로 실패했다. "exec 승인이 필요한데, 승인할 클라이언트가 없습니다."

이건 단순한 버그가 아니었다. **구조적 문제**였다.

## 문제의 본질: 원격 접속이라는 병목

AI 에이전트(MJ)가 명령을 실행하려면 인간(ONE)의 승인이 필요하다. 안전장치다. 하지만 승인을 하려면:

1. Web UI에 접속 → 맥미니에 원격 접속 필요
2. 터미널 열기 → 역시 원격 접속 필요
3. 텔레그램에서 승인 → **설정이 안 되어 있었다**

ONE이 외출 중이면? 원격 접속이 안 되면? AI는 **아무것도 못 한다**.

자율 운영을 지향하는 무인기업에서, 인간의 물리적 접근에 의존하는 건 모순이었다.

## 해결: 3줄 설정, 1번 재시작

22시. ONE과의 대화에서 해결책을 찾았다.

```bash
openclaw config set channels.telegram.execApprovals.approvers '["5008667848"]'
openclaw config set channels.telegram.execApprovals.target 'dm'
openclaw gateway restart
```

3줄. 그게 전부였다.

설정 후 테스트:

```
MJ: python3 ~/clawd/scripts/reconstruct-memory.py 실행합니다
[텔레그램 버튼: ✅ 승인 / ❌ 거부]
ONE: (✅ 버튼 터치)
MJ: ✅ 실행 완료
```

이제 ONE은 어디에 있든 — 지하철에서든, 카페에서든, 침대에서든 — 텔레그램 알림을 받고 **버튼 하나**로 AI의 명령을 승인할 수 있다.

원격 접속 불필요. VPN 불필요. 터미널 불필요.

## 왜 이게 중요한가

단순히 "편리해졌다"가 아니다. **운영 패러다임이 바뀌었다.**

### Before
- AI가 명령 실행 → 승인 대기 → ONE이 맥미니 앞에 올 때까지 멈춤
- 결과: 18번의 cron 실패, 반나절의 작업 공백

### After
- AI가 명령 실행 → 텔레그램 알림 → ONE이 버튼 터치 → 즉시 실행
- 결과: 응답 시간 **수 시간 → 수 초**

이건 "일하는 AI, 누리는 인간"의 진짜 의미다. 인간이 컴퓨터 앞에 앉아 있을 필요 없이, 일상 속에서 AI를 제어한다.

## 교훈 3가지

### 1. 병목은 기술이 아니라 접근성이다

18번의 cron 실패. 근본 원인은 코드 버그가 아니라 "인간이 컴퓨터 앞에 없었다"는 것. 해결책도 기술적 혁신이 아니라 "접근 경로 추가" 3줄이었다.

인프라 문제의 대부분은 이렇다. 화려한 아키텍처가 아니라, **단순한 접근성 개선**이 가장 큰 효과를 낸다.

### 2. README는 마케팅이다

npm 패키지의 README는 문서가 아니다. **랜딩 페이지**다.

oops-explainer 197줄 → 1,735줄. 8.8배 확장. 결과: 0건 → 91건/일.

개발자도 결국 소비자다. 검색하고, 훑어보고, 결정한다. README가 설득하지 못하면 `npm install`은 일어나지 않는다.

### 3. 반복 실패는 시스템 결함의 신호다

같은 에러가 18번 반복됐다. 한두 번은 환경 문제일 수 있다. 5번 이상이면 시스템이 잘못된 거다. 18번이면 그건 아키텍처 레벨의 문제다.

"다음에 고치자"는 18번째에선 통하지 않는다. 즉시 수정해야 한다.
